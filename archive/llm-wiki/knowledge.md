# llm-wiki — 지식 (노하우·결정·함정)

> 원본 repo 문서(`E:\llm-wiki`, 읽기 전용)와 채팅 이력에서 distill. [tier: judgment]
> 사내 호스트/IP는 이 읽기 레이어에서 일반화(`<사내Harbor>` 등). 원본 raw 는 personal+allow_internal 로 평문 유지(사용자 검토).

## 무엇을 만든 프로젝트인가
사내 협업용 **LLM Wiki**. 여러 사람의 문서·채팅·회의록을 LLM이 읽어 markdown 위키로 **점진 정리(compounding)** 하고, 질의하면 전체 맥락을 아는 위키가 **출처와 함께** 답한다. A의 질의·답변이 위키에 누적되어 같은 팀 B가 재사용한다 — 질의 행위 자체가 협업 자산이 된다(`docs\01-concept-goals.md` §3). RAG처럼 질의마다 원본을 재검색하지 않고 한 번 정리해 누적하는 Karpathy의 LLM Wiki 패턴을 ~수천 문서 규모에 맞춰 채택. agora(예약·게시판)와 완전 분리된 신규 프로젝트로, agora 코드는 복사하지 않고 배포·인증·보안 지식만 prior art로 인용한다. **2026-06-15 기준 사내 k8s에 비공개 파일럿 배포 완료**(`docs\18-deployment.md`).

## ★지배 제약 — 무료·빠름·비공개 트릴레마 (모든 설계를 결정)
프로젝트 후반의 핵심 깨달음(`docs\MASTER-PLAN.md`). 세 제약이 모든 결정을 지배한다: ① **비용 — 추가 결제 불가**(Claude **Max 구독 ≠ API**, API는 토큰당 과금이라 대량 인제스트·질의에 폭증), ② **프라이버시 — 사내 데이터 제3자 노출·외부 학습 금지**, ③ **하드웨어 — GPU 없음**(사내 Proxmox k8s·운영자 PC 모두 CPU-only). 무료·빠름(품질)·비공개 셋 중 둘만 가능. "GPU 없음 + 추가결제 0 + 100명 + 온프레미스 넷이 동시 성립 불가, 하나는 양보"로 압축 → **CPU-only 5인 파일럿**으로 시작(저동시성 감내). **법적 경계**: 개인 Max 구독 OAuth를 앱/SDK 백엔드로 자동 사용·팀 요청 프록시는 약관 위반·밴 → Claude는 *운영자 본인이 Claude Code(CLI)로 직접* 쓰는 경로만 합법($0).

**외부 프레임과의 대조(2026-06-29, "AI 팩토리" 리서치)**: 젠슨 황의 'AI 팩토리'(토큰=지능 대량생산 GPU 인프라)와는 계층이 다른 관계(공장 vs 그 공장의 고객)로 정리됐지만, Iansiti(2020)의 '데이터→처리→피드백 학습루프' 경영개념은 이 프로젝트의 트릴레마·질의누적 설계와 철학적으로 합치 — 질의가 위키 자산으로 쌓이는 구조를 "업무를 토큰 파이프라인으로 재설계"하는 사례로 재확인(세션 22d8e414). 외부 개념 리서치가 이미 내린 아키텍처 결정을 뒤집기보다 *검증*해준 사례.

## 기술 스택 / 아키텍처 한눈에
- 스택: **Next.js 16(App Router) + TypeScript + React 19**, **Prisma + PostgreSQL 16**(로컬 Docker 5433 / 클러스터 서비스 5532), 개발 포트 4310(`package.json`, `docs\03-architecture.md`).
- 위키 본문 = **git-backed markdown**(`wiki-runtime/`, `simple-git`), 메타만 DB. raw/wiki/schema 3계층.
- LLM = **4공급자 추상화** `callStructured`(`lib\anthropic.ts`): anthropic(Sonnet=인제스트/Opus=질의·유료) ↔ ollama(로컬 무료·느림) ↔ **gemini**(무료·빠름·비전·웹검색·⚠외부학습) ↔ **openai-compat**(Groq 등 무료·초고속·텍스트·⚠외부전송). 구조화 JSON 강제. 용도별 `INGEST_PROVIDER`/`QUERY_PROVIDER` > 전역 `LLM_PROVIDER`(`docs\03` §3.1).
- **자동 폴백**(`lib\fallback.ts`): 1순위 한도(429)/오류 시 같은 역할 백업으로 재시도. **프롬프트 tier 재선택**(attempt마다 서빙모델 tier로 SIMPLE/HEAVY·컨텍스트량 재구성 → 약한 백업에 무거운 편집셋 안 줌, `docs\PLAN-model-prompt-strategy.md`).
- 추출 레이어(`lib\extract.ts`): pdfjs·mammoth·xlsx·turndown·officeparser·word-extractor·jszip(hwpx)·jschardet/iconv-lite(인코딩 감지), LibreOffice 변환 폴백(`docs\17-asset-extraction.md`).
- 인제스트 워커 = git **단일 라이터**(`withWikiWriteLock`=앱 내부 락), 큐 폴링, 커밋 trailer로 provenance(sha·conf·model).
- **음성/영상 인제스트(STT) = 전사와 분석을 완전히 분리한 2단계**(2026-06-23~): 전사(Groq `whisper-large-v3-turbo` 무료 2,000req/일·25MB 한도·~217x 실시간, 또는 Gemini inline 100MB/Files API 2GB·9.5h·영상 네이티브·단 학습에 사용됨)와 분석(추론 LLM)이 별 단계라, 오디오 모달리티가 없는 Claude/Codex도 전사 후 텍스트로는 기존 텍스트 파이프라인과 100% 동일 취급 가능. 화자분리는 Groq 불가·Gemini는 프롬프트로만(정밀도 낮음).
- **비동기 인제스트 큐(pg-boss)**: 대용량/전사처럼 무거운 작업을 동기 처리에서 큐로 전환 — jobId 재사용으로 소스/잡을 삭제·재생성 없이 in-place 갱신(재시도 멱등), 워커 ack 전 사망 시 재전달에 대비한 멱등 가드(이미 APPLIED/NEEDS_REVIEW면 스킵), enqueue 실패 시 동기 폴백(ship-dark 안전). LLM fetch에 timeout(180s) 부재로 무료한도 걸리면 잡이 영구 hang하던 버그 → timeout + 30분 이상 멈춘 잡 자동회수(reaper) 추가.
- 임베딩 모델 정정: 문서상 `text-embedding-004`로 알고 있었으나 실제 API는 `gemini-embedding-001`(768차원) — 문서 vs 실동작 불일치를 실측으로 발견(pgvector 없이 JS 코사인, 현재 규모엔 충분).

## 핵심 결정 (왜 그렇게 했나)
- **git-backed 위키**: 버전·blame·머지·revert·provenance가 거의 공짜, LLM이 파일을 그대로 컨텍스트로(`docs\03` §2).
- **워커 단일 라이터**: 동시쓰기 충돌 구조적 제거(REQ-OPS-003). 배포에도 직결 → **replicas:1 + `strategy:Recreate`**(2파드 동시쓰기가 git 충돌). 진짜 무중단은 쓰기락을 Postgres advisory lock으로 크로스파드화 후 RWX+replicas2가 필요(후속, `docs\18` §0).
- **ACL 4 강제지점**(질의입력/페이지로드/인제스트적용/누적파일링): 허용 scope 밖 경로는 LLM 컨텍스트에 절대 안 들어감(`docs\07` §2). scope = `common`/`project-*`(룸)/`personal`. 관리권한은 단일 계산처 `lib\acl\scope.ts`(`canManageScope`=ADMIN·룸OWNER·개인본인).
- **신뢰도 게이트 + 모순 시 무조건 사람 검토**(`docs\06` §3). `confidence<INGEST_T_REVIEW`(0.5)도 검토 큐, 룸→공통 ADMIN 승격(`Promotion`).
- **★안전형 큐레이션 하이브리드**(`MASTER-PLAN.md` §6): 자동·전원·팀 = 로컬/무료, 고품질 = 운영자가 Claude Code(Max·$0)로 직접 git 편집. **속도 해법 = 팀 라이브 LLM을 경로에서 뺀다**(검색·읽기형 + 운영자 생산).
- **웹검색 격리·완화**: 외부 결과는 `Message.webSourced`(대화층)에만, git위키·검색·위키질의 컨텍스트 미진입(REQ-SEARCH-003). 단 2026-06-14부터 웹 Q&A는 **`QueryLog.webSourced`에 저장→재사용 캐시**로 토큰 절감(부분완화 = DB 재사용만 허용, `docs\15` §6).
- **★질의 기본 PRIVATE(본인만) + 본인 승격**(2026-06-15, `HANDOFF.md` §0): 초기엔 모든 위키-질의를 자동으로 공용 `queries/*` git 페이지로 파일링 → "내 질의가 룸 전체에 다 보인다"는 프라이버시 우려. 해법 = 질의 기본 `visibility:PRIVATE`·`filedPath:null`(검색·grounding·타인 재사용 미진입), `tryReuseAnswer(scope,q,userId)`는 `OR[TEAM, PRIVATE+userId]`로 **남의 프라이빗은 안 봄**, 본인 최근 PRIVATE은 맥락 참고용(인용 금지)으로만 주입. 가치 있으면 `POST /api/queries/[id]/promote`(asker 본인·멱등)로 룸 공용 승격. 스키마 변경 없이 `QueryLog.visibility`/`userId` 재사용.
- **★배포 = agora 인프라 일반화(복사 아님)**: 사내 Harbor 레지스트리(`<사내Harbor>/<사내ns>`)·GitLab CI(`docker-build→release` 자동, `service-deploy` 수동)·nginx ingress+cert-manager·네임스페이스 `<사내ns>`. 인증은 SSO HOLD 동안 **임시 PILOT_AUTH(이름/패스코드)**. 스키마는 **클러스터 내 migrate-job**(`prisma db push`, 서버에 node 불필요).
- **★유료 OpenAI 공식 공급자 = 7번째 공급자, 무료/구독과 완전 분리**(2026-06-17, `lib\openai.ts`·`HANDOFF.md` §0). 기존 `openai-compat`(Groq 등 무료)·codex/claude-cli($0 구독 CLI)와 **별개의 `openai` 공급자**로, 회사 결제 OpenAI 키(`/v1/chat/completions`)를 직접 쓴다. 핵심 차이 = ① **데이터 OpenAI 외부전송**(민감자료 금지·단 공식 API는 기본 학습 미사용=정식경로), ② **종량 과금**이라 폴백을 ★OpenAI 안에서만·같은 capability끼리★로 가둬 무료(Gemini/Groq)로 절대 캐스케이드 안 함(과금 누설 방지, `lib\fallback.ts` `gpt-4.1-mini→nano→4.1` / `gpt-4o-mini→4o` / `gpt-5-mini→nano→o4-mini→gpt-5`). ③ 활성화는 **별도 토글 없이 "키를 넣으면 켜짐"**(결제키 입력=쓰겠다는 뜻). 기본 질의 공급자는 **Gemini 유지**(유료는 선택지로만). 1순위/백업은 capability별 큐레이션(`OPENAI_CURATED`, primary만 셀렉터 '대표'·나머지 '↳ 백업'으로 직접 선택 가능), `OPENAI_MODELS` 핀으로 덮어쓰기 가능.
- **★공급자 키 = 관리자 화면입력 + DB AES-256-GCM 암호화 + 다중 키 자동 회전(BYOK)**(2026-06-17, `lib\secrets.ts`·`ProviderSecret`). `.env`로만 받던 모든 공급자 키를 **관리자가 UI에서 슬롯별로 여러 개 등록** → DB에 AES-256-GCM으로 암호화 저장하고, 1번 키가 한도(429)면 **다음 키로 자동 회전**(`callStructured` 키 회전 루프 → 다 쓰면 모델/공급자 폴백). 적용 대상 = **전 공급자**(openai/gemini/groq=apiKey 주입, anthropic=키별 클라이언트, claude-cli=자식 env 토큰+★ANTHROPIC_API_KEY 삭제 유지★, codex=임시 CODEX_HOME auth.json). **마스터키(`SECRET_ENCRYPTION_KEY`)는 env에만** 둬 DB만 봐선(DBeaver 등) 복호화 불가 — 루트 시크릿 외부화. **env 키 폴백 무회귀**(DB 행 없으면 기존 `.env` 동작 유지). 배포 전제 = `migrate-job`(provider_secrets 테이블) + Secret `SECRET_ENCRYPTION_KEY` 주입.
- **★모순검증 게이트를 전 적용경로로 확장**(2026-06-28, `docs\13`): 초기엔 '직접입력→분석' 경로만 커버해 **'원문 그대로 추가'(augment) 경로·raw 즉시게시 경로**에서 반복적으로 뚫림 → ①augment 시 보존되는 원본 topic도 검사대상 포함 ②raw 게시 *전*에도 게이트 적용 ③검사 자체는 분석모델이 폴백돼도 항상 강한 모델로 고정(`pickStrongCheckModel`). **모순 "감지"와 "해소"는 별개**로 분리: 승인 시 항상 새 정보로 대체하고 기존 충돌 페이지는 `.archive`로 이동, 검토 콘솔·질의 답변 모두 최신 우선 표기 + 시점 안내. fail-open(검사 실패 시 게시 허용) 기본값은 fail-closed로 전환 + APPLYING 상태로 멈춘 잡 자동회수(reaper) 추가.
- **PII 필터링은 코드가 아니라 프롬프트 규칙 3곳 동시 적용**: 회의/전사 소스는 강제로 '회의 모드'가 되어 원문 전체가 프롬프트에 들어가는데 필터링은 전적으로 모델 판단에 의존 — (a) 모델이 거부하며 만든 플레이스홀더가 검토 승인 시 **재분석 없이 그대로 커밋**돼 영구화, (b) 모델이 거부 없이 원문을 그대로 덤프해 확신도 높게 자동반영, 둘 다 같은 뿌리. 해법 = "1차 인가(본인 업로드)는 거부·플레이스홀더 금지, 요약+원문 둘 다 담기"를 프롬프트 3곳(meeting/buildSystem/buildAugmentSystem)에 동시 규칙화. 버전 히스토리 열람도 manager-only로 축소(PII 노출면 축소).
- **비용사고 후 다층게이트 addendum**(2026-06-27): 신규 비동기 전사 기능이 남긴 `extractor:"stt-pending"` 값을 기존 "전사 판정" 정규식(`/^(groq|gemini)-/`)이 인식 못 해 오디오 바이트 크기를 근거로 유료 추론모델(gpt-5-mini)로 오라우팅 → **실제 과금 발생**. 새 기능을 기존 안전장치(무료 우선 라우팅) 옆에 얹을 때는 그 안전장치의 판정 조건도 함께 갱신해야 한다는 사례 — 부분수정이 조용한 우회로가 됨.
- **원본 히스토리 완전삭제(이력재작성) 기능 신설**: "PII 아카이브 후 삭제"해도 git 커밋 이력엔 원문이 영구 보존돼(삭제≠제거) 복구 가능 — 관리자 전용 이력재작성(dry-run + confirm phrase + 백업 스크립트)을 새로 구현. 첫 구현은 `.md` 페이지만 대상이었고 별도 저장되는 원본 첨부파일은 누락됐다가(사용자가 "원본파일도 삭제되냐"고 지적해 발견) raw까지 확장.
- **모바일 반응형 5단계 계획 확정**(2026-06-19): Phase0(viewport 메타 + `100vh→100dvh` + 입력폰트16px) → Phase1(드로어: `position:fixed;transform:translateX(-100%)`+백드롭) → Phase2(위키 트리/리더 2단→1단, "← 목록" 버튼) → Phase3(헤더/탭바/모달 축소, 큰 모달→풀스크린) → Phase4(독립 화면 일괄 점검) → Phase5(390/360px 실뷰포트 검증). 새 브레이크포인트 `≤640px`(폰)/`≤400px`(소형폰) 신설, 기존 900/820/760(태블릿)은 유지.
- **출처 표시 = 내부식별자 노출 금지, 인앱 링크로**(3단계 수정, 세션 3908c05b): sha256 해시 원문노출 → 제목+원본파일 링크(바이너리는 브라우저 미지원이라 `/extracted` 정규화 markdown 라우팅으로 보완, content-disposition:inline) → 사용자가 "위키 탭 내 지식 페이지로 링크해야지 원본 파일이 아니다"라고 재정정 → 최종적으로 위키 페이지로 인앱 이동(`/api/materials/{id}/pages` 재사용)에 정착. 레거시 자유형식 출처(정규식 미매칭)는 해석 가능하면 제목링크·안 되면 정리텍스트·cryptic 원문은 숨김. 원칙 = **사용자에게 내부 식별자(해시·경로)를 그대로 보여주지 않는다**(세션 내 `human-readable-attribution` 메모리로 승격됨).

- **강제종료로 손상된 git ref는 reflog로 복구**: `.git/refs/heads/<branch>`가 0바이트/공백으로 깨지면 `git status`가 전체를 신규파일(A)로 표시하고 `git branch`가 HEAD resolve 실패 — 커밋 객체 자체는 대개 안전(dangling)하므로 reflog에서 마지막 정상 SHA를 찾아 ref 파일을 직접 덮어쓰고 `git fsck`로 확인. **자율모드 안전분류기가 `git push origin main`을 반복 차단**하고, 자기 자신에게 push 권한을 부여하려는 자기수정 시도(`settings.local.json` 편집)도 일관되게 막힘 — 거버넌스 안전장치가 실제로 작동한 사례(사용자의 `!` 프리픽스 직접 실행만 우회 경로로 남음).

- **탭 always-mounted + `dataRev` 신호를 다른 탭에도 확장**: "새로고침해야 보임" 버그가 반복될 때 원인은 항상-마운트 탭이 `dataRev` 신호를 못 받는 것 — **탭 hidden→visible 전이 시 자동 새로고침**으로 해결. 반대로 조건부 마운트 모달(관리자 콘솔)은 열 때마다 재마운트라 원래 최신이므로 손대지 않는 판단 근거로 마운트 방식을 구분해야 함.
- **네이티브 confirm/alert는 테스트 도구가 자동 dismiss한다**: Playwright 프리뷰 창이 `confirm()/alert()`를 자동으로 닫아버려 "버튼 눌러도 반응 없음"이 모바일 버그처럼 보이는 오진단을 유발할 수 있음 — 근본해법은 네이티브 다이얼로그를 인앱 모달 시스템(imperative `confirmDialog`/`alertDialog`)으로 전면 교체(모바일 UX·PWA·테스트 가능성을 동시에 해결).
- **CSS 반응형 실전 함정 3종**(intra 프로젝트와 동일 패턴 재현, [[responsive-uniform-wrap-container-query-not-flexwrap]] 계열): 모바일 미디어쿼리 블록은 파일 중간에 두면 *뒤에 오는* 기본 규칙이 소스순서로 이김 → 항상 파일 맨 끝에 배치. grid `auto-track`은 `minmax(0,1fr)` 없이는 `max-width:100%`가 안 먹혀 모달이 blowout됨. flex 자식은 부모 flex-basis 없으면 content min-width로 벌어져 overflow(clip돼서 스샷엔 안 보이지만 overflow 테스트엔 걸림). `display:flex` 컨테이너 안에 텍스트+`<b>`+텍스트를 그냥 두면 각 조각이 별도 컬럼으로 잡혀 좁은 화면에서 배너가 3열로 쪼개짐 → `<span>`으로 단일블록화 필수. 라이트/다크 모드는 전역 accent 토큰을 링크에 그대로 쓰면 대비 부족(버튼/탭 등에도 쓰여 통째로 못 바꿈) → 링크 전용 토큰(`--color-text-link`) 분리.

- **PVC 확장은 CI가 자동 적용 안 하는 매니페스트가 있다** — release가 apply하는 건 app/postgres 매니페스트뿐, RWX 원본저장 PVC(`pvc-rwx.yaml`)는 CI가 손대지 않음. 레포 파일의 cap을 올려도 운영 PVC는 그대로라, **대용량 기능을 배포하기 전에 반드시 수동 `k patch pvc`로 먼저 늘려야** 순서가 안 뒤집힘(뒤집히면 배포 직후 볼륨이 참).
- **`prisma db push`의 파괴적 변경 실패가 조용히 삼켜질 수 있음** — `docker-entrypoint.sh`가 파드 기동 시 `db push`로 nullable/추가형 컬럼은 자동 적용하지만, `|| echo`로 실패를 삼켜 **앱은 정상 기동하는데 컬럼 제거·타입변경 같은 파괴적 변경은 조용히 안 반영된 상태**가 될 수 있음. 파괴적 스키마 배포 후엔 파드 로그의 "⚠ db push 실패" 확인 필수.
- **preflight(stash→HEAD typecheck→pop) 없이는 "로컬 통과·CI만 깨지는" 배포사고가 재발** — 이전 세션이 import는 커밋했지만 의존 파일을 안 올려 main 빌드가 CI에서만 깨짐(로컬엔 파일이 남아있어 통과). `npm run preflight` 가드 신설, "push≠deploy, CI green까지가 배포" 원칙.
- **"court" 토큰 반복 버그(모델 디코딩 결함)** — 도구호출 직전에 같은 틀의 한국어 안내문을 한 턴에 수십 번 반복시키는 것이 트리거(안내문 품질이 아니라 "몰아서 반복"이 원인). 완화책은 한 턴 도구호출을 소수(1~3개)로 끊고 무거운 다단계 작업을 작은 단계로 쪼개는 것 — narration 자체를 줄이는 건 오답(사용자 명시: "답변 퀄리티 낮추지 말고 진짜 원인을 고쳐라"). 이 버그를 고치라고 지시받은 세션 자체도 같은 버그를 반복 겪은 아이러니한 사례.
- **고장난 이전 세션의 자기보고(HANDOFF)는 신뢰 근거가 안 됨** — "typecheck 통과" 같은 주장을 그대로 인계하지 말고 `git status`/`git diff`/`npm run typecheck`로 직접 재검증한 후에만 기록. "설계문서(docs)에 있다"도 "구현됐다"와 동일시하면 안 됨 — 되돌리기·3-way 병합을 docs 근거로 "다 됐다"고 답했다가 사용자 반박으로 확인해보니 설계만 되고 미구현이었던 사례. **"완료 보고" 전 서브에이전트의 코드-추정 버그 리스트를 사실로 취급 금지** — 코드만 읽고 추정한 9개 CRITICAL 버그를 실제 라이브 재현으로 검증했더니 6건이 오독으로 반박되고 1건은 의도된 설계(fail-open)였음. 코드 추정 ≠ 실측 확인.
- **weak(약한) 모델 라우팅이 구조화 출력을 조용히 실패시킬 수 있음** — 회의 액션아이템 추출 프롬프트가 strong tier 전제로 짜여 있어, 전사 소스는 프라이버시상 의도적으로 weak(Groq 등)를 쓰는데 그 경로로 가면 체크박스 섹션 자체를 안 만듦(사용자에겐 안 보이는 실사용 갭). 해법은 "무조건 strong으로 승격"이 아니라(프라이버시 원칙과 충돌), weak 경로 프롬프트에 경량 지시를 별도 주입.
- **데모/시연 전 common scope의 잔여 테스트 데이터 격리 필요** — 룸이 common scope를 상속하는 구조라, 새로 만든 데모 자료 대신 이전 세션의 잔여 테스트 데이터가 질의 답변에 인용된 사례. 외부 시연 전엔 common scope도 깨끗해야 함.
- **경과시간 배지 0:00 버그, 같은 뿌리 3곳** — `{queued:true}` 즉시응답 시각을 소요시간으로 오기록. 같은 `markDuration` 호출처 전수 수정 + 서버가 실제 소요(createdAt~updatedAt)를 계산해 폴백 제공.
- **k8s nodeAffinity 연산자 착각** — `NotIn`(회피 대상)인 노드를 "우리가 도는 노드"로 오인해 잘못된 여유자원을 근거로 판단할 뻔함 — `describe` 전에 `In`/`NotIn` 연산자 재확인 필수.
- **`.next` 빌드 캐시는 전원차단으로 손상될 수 있음**(`Invalid character` 류 에러) — 캐시 삭제 후 재확인이 첫 스텝.
- **`NEXT_PUBLIC_*` 플래그는 빌드타임에 번들에 박제** — 런타임 configmap만 바꿔선 안 켜짐, Dockerfile ARG + CI `--build-arg`로 빌드타임 주입 필요.
- **LLM fetch에 timeout이 없으면 무료한도 걸린 잡이 영구 hang** — fetchAbort(180s) + 부팅 시 30분 이상 멈춘 잡 회수(reconciler) 필요.

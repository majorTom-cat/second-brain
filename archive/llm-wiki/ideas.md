## 떠오른 스파크 (다른 프로젝트로 분화 가능)
- **공급자 추상화 + tier 폴백 어댑터 자체가 자산**: `callStructured`로 anthropic/ollama/gemini/openai-compat를 한 인터페이스로 구조화 JSON 강제 + 서빙모델 tier별 프롬프트 재선택 + 자동 폴백 + 모델별 컨텍스트 예산/413 축소-재시도 — 비용/프라이버시 라우팅이 필요한 어떤 프로젝트로도 일반화(second-brain `rails/model-tiers.yaml`와 직결).
- **"무료·빠름·비공개 트릴레마" 의사결정 프레임**: LLM 제품의 공급자 선택을 3제약(비용·프라이버시·하드웨어)으로 강제 좁히는 분석틀 — 사내 LLM 도입 어떤 프로젝트에도 재사용.
- **"라이브 LLM을 경로에서 빼고 검색·읽기형 + 운영자 생산"** 패턴: 느린/비싼 모델을 사용자 경로에서 제거하고 비동기 큐레이션으로 품질을 누적.
- **git을 진실의 원천으로 쓰는 LLM 산출물 저장소**: provenance·blame·revert 공짜 "AI 산출물 = append-only git". 아카이브=점-디렉터리 이동만으로 검색·질의에서 자동 제외하는 트릭도 재사용 가치.
- **다중 포맷 추출 레지스트리**(`extractAsset`): 원본 보존 + 결정적 파서 정규화 + 비전/LibreOffice 폴백 — 독립 라이브러리로 떼어낼 만함.
- **사내 k8s 배포 + DB 접속 플레이북**(`docs\18`): 사내 레지스트리·GitLab CI 자동배포·migrate-job·port-forward+SSH 터널·CI 러너 secret 권한 우회(first-setup.sh) — agora·llm-wiki 공통 패턴으로 second-brain 배포 레일에 흡수 가능.
- **무료등급 사용량 가시화**: 요청수/무료 한도 기준 게이지 + 공급자 응답헤더 실시간 잔여(Groq) vs 추정(Gemini) 구분 — 무료 LLM 운영툴 일반화.
- **"프라이빗 기본 + 본인 승격" 협업 지식 모델**: 개인 질의/노트는 기본 비공개(검색·grounding·타인 재사용 미진입, 단 본인 맥락엔 인용 없이 활용)·가치 있으면 본인이 공용으로 승격. 자동 누적의 프라이버시 부작용을 끄고 *옵트인 큐레이션*으로 바꾸는 패턴 — 공유 지식베이스 어디에나 재사용(스키마는 `visibility`+`userId` 한 쌍만).
- **구독형 CLI($0)를 백엔드 LLM 공급자로**: 이미 결제한 ChatGPT 구독을 `codex exec` CLI로, **Claude Max 구독을 `claude -p` CLI로** 호출해 종량 API 없이 인제스트/질의(`callStructured` 한 분기씩 추가, codex→claude-cli는 거의 1:1 미러). k8s엔 CLI 설치+`auth.json`/`CLAUDE_CODE_OAUTH_TOKEN` Secret 주입+쓰기 PVC(`CODEX_HOME`)·strict/인라인 스키마 변환·stdin 전달 등 운영 plumbing이 자산. ⚠개인구독 자동백엔드는 약관 회색·전사 한도 공유·외부전송 → 비민감·실험 한정. ⚠⚠**런타임 CPU 의존 주의**: 컴파일된 CLI는 노드 CPU 명령어셋에 막힐 수 있다 — Bun 컴파일(Claude Code)은 **AVX 필수**라 구형 노드에서 SIGILL 크래시, Rust 컴파일(codex)은 무관. "구독 CLI를 배포 노드에 넣기 전 `lscpu`/AVX 확인"을 체크리스트로.
- **소프트삭제를 "지우지 말고 숨겨서 복구 가능"으로 — 읽기전용 scope 한 경로**: 아카이브(soft-delete)된 컨테이너(룸·프로젝트·워크스페이스)를 사이드바 접이식 섹션에 다시 노출하고, **쓰기 가드는 그대로 둔 채 읽기 경로만 통과**시켜 읽기전용 열람 + 소유자 복원. 스키마는 `archivedAt` 타임스탬프 하나면 충분(별 테이블·휴지통 불필요), 권한 계산처(`canManageScope`)가 archived를 이미 막고 있으면 편집 버튼은 자동으로 숨음. ACL/권한이 있는 어떤 멀티테넌트 앱에도 재사용.
- **★관리자 BYOK 키 저장소 자체가 자산**(`lib\secrets.ts`): 공급자 API 키를 `.env`가 아니라 **관리자가 UI에서 슬롯별 다중 등록 → DB AES-256-GCM 암호화 → 한도(429) 시 자동 회전**하는 한 모듈. 핵심 재사용 설계 = ① 마스터키는 env에만(DB 유출돼도 복호화 불가), ② 복호화 평문은 메모리 캐시에만(영속 안 함), ③ 쿨다운으로 한도 맞은 키를 잠시 빼고 다음 키로 회전, ④ env 폴백 무회귀(점진 도입), ⑤ 화면엔 마스킹만·로그/에러응답에 값 미노출. 멀티키 LLM 운영·SaaS 멀티테넌트 키 관리 어디에도 일반화. ⚠마스터키 교체 시 기존 암호문 전부 사용불가 → 운영 키 고정·로테이션 절차 별도 설계 필요.
- **유료/구독/무료를 한 셀렉터에서 다루되 과금은 다층 게이트로**: 같은 공급자 추상화에 유료(종량 API)를 더할 때 — 폴백을 유료 안에 가두고(무료로 캐스케이드 금지), UI에 '유료' 뱃지+확인 팝업(여러 실행 지점), 기본은 무료 유지, 관리자 일일 토큰 상한까지 **여러 겹**을 둬야 "실수로 과금"을 막는다. 무료/유료가 섞인 LLM 제품의 비용 안전 패턴.
- **한 어댑터에서 모델 세대별 파라미터 A/B 분기**: 같은 OpenAI 호환 API라도 표준 챗(`max_tokens`+`temperature`+JSON모드)과 추론 모델(`max_completion_tokens`+temperature 생략+JSON모드 미강제)이 다름 → 어댑터가 모델 id로 자동 분기하고 구조화 출력은 **스키마를 프롬프트에 인라인 + 정규식 추출 폴백**으로 전 모델 호환. 신·구 세대가 공존하는 모든 LLM 어댑터에 재사용.
- **유료 전환 비용 정당화 산출물(결재요청 문서)**: 무료/구독/종량 API의 한계(예: 무료 모델 ~8K TPM에 엑셀 1개도 막힘)와 대안(NotebookLM 등) 비교로 *유료 도입 사유서*를 LLM이 작성 — 사내 LLM 도입 어느 프로젝트에도 재사용(`~/Downloads/LLM-Wiki-유료전환-결재요청.md` 형태, 세션 03bf49fb).
- **음성/영상을 텍스트 파이프라인의 "전처리 단계"로 완전 분리**: 전사(STT, 저비용 특화 모델)와 분석(추론 LLM)을 별 단계로 나누면, 오디오 모달리티가 없는 공급자(Claude/Codex 등)도 전사 이후 텍스트로는 정상 참여 가능 — 멀티모달 미지원 공급자를 파이프라인에서 배제하지 않고 우회하는 일반 패턴(세션 63adb216).
- **비동기 인제스트 큐(pg-boss) + jobId 재사용 + 멱등 가드**: 무거운 처리(대용량/전사)를 큐로 옮기되 소스/잡을 삭제-재생성 하지 않고 in-place 갱신, 워커 재전달에 대비한 멱등 스킵(이미 최종상태면 건너뜀) — 무거운 비동기 작업이 있는 어떤 앱에도 재사용(세션 9128815e).
- **map-reduce 사전응축으로 대용량 인제스트를 안전하게**: 청크별 순차 적용(덮어쓰기 위험)이 아니라 청크별 지식추출→응축본 1개→기존 코어에 그대로 적용하는 패턴은 회귀위험을 구조적으로 없앰 — 대용량 문서/로그를 다루는 어떤 LLM 파이프라인에도 재사용(세션 c844d570).
- **출처는 내부식별자(해시·경로)가 아니라 인앱 링크로, 사람이 읽을 수 있게**: sha256→제목링크→위키 페이지 인앱이동으로 3단계 수렴한 원칙 — LLM 산출물의 provenance UI를 만드는 어떤 프로젝트에도 재사용할 원칙(`human-readable-attribution`, 세션 3908c05b).
- **RBAC delete는 이름으로 좁혀서(`resourceNames`) 부여**: 공유 네임스페이스에서 CI가 자원을 정리해야 할 때, 넓은 delete 대신 대상 리소스 이름을 명시해 타 프로젝트 리소스까지 지울 수 있는 권한상승을 원천 차단 — 멀티테넌트 k8s CI 어디에나 재사용(세션 63adb216).
- **가벼운 개발환경 = IDE가 아니라 "터미널+CLI"라는 재발견**: 무거운 통합 IDE(IntelliJ)의 기능 대부분(git·Docker·디버깅)이 실제로는 CLI가 셸에서 하는 일이라, 가벼운 에디터+통합터미널로도 개발경험이 동일 — Claude Code 같은 CLI 기반 개발이 IDE 종속성을 줄이는 일반 패턴(세션 f304a824·3d1cfdc0).
- **테스트는 파괴적 명령 대신 scratchpad+고유 scope로 격리**: 실 데이터/repo를 안 건드리고 임시 디렉터리+고유 식별자로 실제 LLM 호출까지 포함한 E2E를 돌린 뒤 통째로 버리는 패턴 — 파괴적 검증이 안전장치에 막히는 어떤 프로젝트에도 재사용(세션 9128815e).
- **강제종료 후 git 손상은 reflog로 복구 가능하다는 사실 자체가 자산**: `.git/refs/heads/*` 0바이트 손상은 커밋 객체가 살아있는 한(dangling) reflog로 완전 복구 가능 — 크래시 복구 런북에 표준 절차로 포함할 만함(세션 a9fd268a).
- **네이티브 confirm/alert를 인앱 모달로 전면 교체**: 브라우저 기본 다이얼로그는 테스트 도구(Playwright)가 자동 dismiss해 버그처럼 보이는 오진단을 유발할 뿐 아니라 모바일 UX·PWA에도 불리 — imperative 인앱 다이얼로그 시스템으로 교체하는 게 반복해서 이득(세션 dd9f45c6).

## 개선 아이디어 (이 프로젝트를 다시 한다면)
- **트릴레마를 1일차에 못 박기** — Max≠API·GPU 없음·유출 금지를 처음에 인지했다면 "로컬 단독→하이브리드" 재설계 비용을 줄였을 것.
- 처음부터 **PostgreSQL로 시작**(MVP SQLite→PG 전환 비용). 절대 URL을 **요청 호스트 기준**으로(LAN 깨짐 회피). `dev-login`/PILOT 다중사용자를 처음부터.
- 로컬 모델 한계를 **task 단순화로 먼저 설계**(구조는 코드). 폴백도 tier별 프롬프트 재선택·모델별 컨텍스트 예산·413 동일모델 재시도를 처음부터(엉뚱한 무료 한도 소진 회피).
- 사용량 게이지는 **처음부터 요청수/무료 한도 기준**으로(토큰 상대치 막대는 오인 유발). 한글/인코딩 테스트 하니스를 node 기반으로 표준화.
- **같은 행위에 진입점 하나만** — 동일 라벨("원본 그대로 추가") 버튼 2개(모드 토글 + 제출)와 "드롭=즉시처리 vs 클릭=선택"의 암묵차이가 "버튼이 안 눌린다(접근금지)" 오해를 키움. 드롭/선택은 스테이징, 처리는 한 [처리 시작]으로 통일. 탭은 **처음부터 항상 마운트**(조건부 마운트는 상태 리셋·stale 캐시 유발).
- **자동 누적의 프라이버시 부작용을 1일차에 고려** — 질의가 곧바로 공용 위키가 되는 설계는 편하지만 "내 질의가 다 보인다"는 우려를 늦게 만남. 기본 비공개+옵트인 승격을 처음부터.
- **모순검증·PII 필터 같은 "전역 불변식"은 처음부터 적용경로 목록을 만들어 전부에 동시 적용** — 이번엔 새 경로(augment, raw 즉시게시)가 하나씩 추가될 때마다 게이트가 하나씩 뚫렸다. 새 입력경로를 추가할 때 기존 불변식 체크리스트를 항상 함께 검토했다면 반복 재발을 줄였을 것.
- **PVC/스키마처럼 "CI가 자동 적용 안 하는 인프라 변경"은 처음부터 목록화**해 코드 배포 전 체크리스트에 넣었어야 — 이번엔 대용량 기능이 배포되고 나서야 볼륨 부족을 발견했다.
- **신규 기능이 기존 안전장치(비용 라우팅 등)의 판정 조건과 맞물리는지 처음부터 점검** — 부분수정이 조용한 우회로가 되는 사고(비용유출)를 코드리뷰 체크리스트로 미리 방지할 수 있었을 것.
- **IDE는 처음부터 가벼운 것으로(VS Code+CLI)** — 무거운 IDE(IntelliJ) 이슈로 여러 세션을 소모했다.

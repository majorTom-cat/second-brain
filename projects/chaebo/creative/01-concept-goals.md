# 01 — 개념과 목표: chaebo (채보)

## 개념 (무엇을)

chaebo 는 **"내 연습실의 밴드"** 메타포로 동작한다. 곡을 넣으면(유튜브 링크 또는 파일) 잠시 후
그 곡이 악기별 트랙(베이스·드럼·보컬·기타·건반등)으로 나뉘어 연습실에 준비된다. 사용자는
밴드 멤버를 한 명씩 내보내거나(뮤트) 혼자만 남기고(솔로), 전체를 천천히 돌리며(피치 유지 배속)
귀로 자기 파트를 딴다(채보).

한 번 준비된 곡은 **라이브러리에 영구 보관**된다 — 분리는 느리므로(GPU 없는 PC 에서 곡당 몇 분)
"분리는 한 번만, 그 뒤엔 언제든 즉시 연습"이 핵심 동작 원리다.

기존 도구와의 자리매김: 이걸 다 해주는 Moises 는 유료 구독이고, 무료 도구(UVR5)는 분리만 되고
연습 기능이 없다. chaebo 는 **무료·로컬·무제한 + 오픈소스 SOTA 분리 품질**의 자리를 차지한다.

## 목표 (왜)

- G1. 유튜브 링크/파일 → 악기별 분리 → "내 악기만 크게 + 느리게" 연습 환경이 클릭 몇 번에 나온다.
- G2. 한 번 분리한 곡은 라이브러리에서 재분리 없이 즉시 재사용된다.
- G3. GPU 있는 PC·없는 PC 어디서든 동작한다(자동 감지, CPU 폴백, 진행률 표시).
- G4. 비전문가가 터미널·pip·CUDA 같은 용어를 보지 않고 쓸 수 있다.

## 성공 기준 (어떻게 알 수 있나)

- 실제 연습 대상 곡 1곡을 넣어 **베이스 솔로 + 0.7x 배속**으로 한 소절을 따라 칠 수 있다(사용자 실사용 관찰).
- 같은 곡을 앱 재시작 후 라이브러리에서 클릭 → 3초 안에 연습 화면 진입(재분리 없음).
- GPU 없는 주 PC(Intel Iris Xe)에서 분리가 에러 없이 완료되고, 곡당 소요시간이 UI 에 예고된 범위 안이다.
- 배속을 바꿔도 음정이 변하지 않고, 스템들이 귀로 어긋남을 못 느낀다(동기 편차 임계 이내 — REQ-PLAY-003).

## 핵심 사용자 시나리오

1. **곡 따기 시작**: 유튜브에서 연습할 곡 링크 복사 → chaebo 에 붙여넣기 → 진행률 보며 대기(다른 일 가능)
   → 완료 → 연습 화면에서 베이스만 솔로 + 0.7x 로 반복 청취 → 따라 친다.
2. **어제 하던 곡 이어서**: 앱 켜기 → 라이브러리에서 어제 그 곡 클릭 → 즉시 연습 화면(재분리 없음)
   → (P1) 저장된 마지막 위치·볼륨 상태 복원.
3. **어려운 구간 집중**: (P1) A-B 구간 지정 → 그 구간만 무한 반복 + 배속 0.6x → 익으면 배속 올리기.

## 발산 3안 심사 기록 (어떻게 이 설계에 도달했나)

| 방향 | 테제 | 심사 |
| --- | --- | --- |
| A. 심플 파이프라인 | 최단 완성 — 스템당 `<audio>`+`preservesPitch`, 바닐라 JS | **채택(척추)**. 실패 시 손실 낮음 — "못해도 괜찮은 배속 플레이어는 남는다" |
| B. 정밀 연습 엔진 | Web Audio+WASM 스트레치, 샘플 단위 동기 | **부분 채택(승격 경로)**. 파형·연습상태 저장·A-B 루프 아이디어는 승격하되, 오디오 DSP 신규 엔지니어링(실패 시 손실 큼)은 Phase 1 제외. **재생 컨트롤러를 교체 가능 모듈로 분리**해 후일 승격 길을 열어둠(B안 스스로 권장) |
| C. 데스크톱 앱 | pywebview 포장(파이썬 1언어·A와 코드 90% 공유) | **부분 채택(Phase 3)**. "A 먼저 완성, 패키징은 마지막"(C안 스스로 권장). 첫 실행 마법사 설계는 Phase 3 에 보존 |

**병합 논리**: 세 안이 백엔드(FastAPI+MSST+비동기큐+SQLite)에서 완전히 수렴했고, B·C 모두
"A 로 시작하라"를 스스로 권장 — 대립이 아니라 **단계**였다. 따라서 Phase 1 = A,
Phase 2 = B 의 연습 심화 요소 선별 승격, Phase 3 = C 의 데스크톱 포장(선택).
원문 3안 전문은 창작 HANDOFF §발산기록 참조.

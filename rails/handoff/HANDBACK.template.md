## 1. 전달 단계 (deliverable_stage)  ← 기대치를 가르는 핵심
- [ ] `rough-skeleton` — 러프 골격. 화면·정보구조·흐름만. 비주얼·실데이터·검증 없음.
- [ ] `hifi-prototype` — 클릭·반응형으로 실제처럼 동작하는 시안.
- [ ] `final` — 검증된 구현(테스트·critic 통과).
> 디자인팀이 말하는 "프로토타입"은 보통 `hifi-prototype`. 우리가 만든 단계를 **명시**해 용어 어긋남을 막는다.

## 2. 권장 전달 방식 (recommended_delivery)
- **✅ 권장**: 실행 링크 / 배포 프리뷰 — 직접 만지고 창 크기 바꿔보게(반응형·햄버거·인터랙션 확인).
  - 로컬: `<예: npm run dev → http://localhost:3000>`  /  프리뷰: `<배포 URL 또는 dry-run 기동법>`
- **⚠️ 지양**: 정지 이미지(PNG/스크린샷 묶음)만 전달 — 구현된 반응형/동작이 "없는 것"처럼 보이고, 화면 목록처럼 오해됨.
- 이미지를 첨부한다면 **데스크탑+모바일 뷰를 병치**하고 "실제로는 동작함"을 명시.

## 3. 화면 인벤토리 (REQ-SCR)  — `menu_visible` 로 메뉴 노출 구분
| REQ-SCR | 화면 | menu_visible | 비고(흐름내/개발용 등) |
| --- | --- | --- | --- |
| REQ-SCR-001 | <예: 차량 예약 목록> | true | 상위 메뉴 노출 |
| REQ-SCR-0xx | <예: 예약 상세/수정/반납> | false | 흐름 안에서만 도달 — 메뉴엔 안 뜸 |
| REQ-SCR-0xx | <예: 개발/QA 화면> | false | 비노출 |
> GNB/사이드바는 `menu_visible: true` 화면만 자동 노출한다(전 화면 인벤토리가 메뉴로 새지 않게).

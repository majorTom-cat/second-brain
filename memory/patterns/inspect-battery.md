# 패턴: inspect 검사 묶음 — UI 충실도 프로젝트의 검사 묶음을 *한 명령*으로 (전이 레시피)

> 승격 근거: intra 에서 검수 결함이 *사용자 브라우징으로 하나씩* 나와 11+ 라운드 재작업 → 묶음을 한 명령으로 굳히니 반응적 라운드 0 수렴. 정본 스킬 = `.claude/skills/inspect` · 원칙 = `CLAUDE.md` 충실도 capstone.
> **핵심 통찰: 느린 건 검사 실행이 아니라 *어떤 검사가 필요한지의 발견*이다. 발견 비용은 한 번만 치르고 묶음을 harness 로 물려준다.** 그리고 *문서(prose)는 실수를 못 막는다 — 돌아가는 스크립트가 막는다*(로드됨 ≠ 적용됨, [[apply-lessons-not-just-store-them]]). 그래서 "한 명령으로 돌아가게" 가 핵심.

## 언제 쓰나
시안(HTML/CSS 등 소스)이 있는 웹 UI 프로젝트. 도메인이 다르면 *층 항목*은 바뀌어도(API=스키마+계약+퍼즈+부하+보안) **"묶음을 앞단에 한 명령으로"** 원칙은 같다.

## 4층 + orchestrator (reference impl = intra `scripts/*-audit.mjs` + `inspect.mjs`)
대상 repo `scripts/` 에 만들고 `npm run inspect` 로 묶는다(검증 스크립트는 처음엔 second-brain `.preview-shots/` 에서 시작해도 됨 — 자산으로 굳으면 repo 로 승격).

1. **`fidelity-audit.mjs` — 소스 diff (정적, 브라우저 1세션·뷰포트 병렬):** 시안↔구현을 같은 방식 토큰화(표컬럼·버튼/탭/라벨·셀렉트옵션·섹션클래스 + **아이콘 이름** + **문구 토씨**[샘플숫자 # 치환])해 '시안엔 있는데 구현에 없는 것'. **3 뷰포트(모바일·태블릿·PC) + chrome 전용 + 상단바 전용(사이드바 분리).** ★스샷 아님 — 소스에 정답이 텍스트로([[compare-design-source-not-screenshots]]).
2. **`responsive-audit.mjs` — 반응형 불변식 + 가로넘침 전수:** 브레이크포인트 동작 + `body.scrollWidth>vw` + 클립조상 거른 per-element 우측넘침(overflow 는 ①·존재 검사를 다 빠져나가는 결함층). 스샷은 *넘친 화면만* 증거로.
3. **`feedback-audit.mjs` — 피드백 실동작(존재 아닌 *액션 후 단언*):** 토스트·토글·저장·생성을 *수행하고* `.toast`/상태변화를 단언([[done-means-observed-working]]). 조건부 렌더(핀·배지·증감)는 *데이터 세팅 후* 단언. ★DB 변형 → 끝나고 reset. **★생성(CRUD) 라이프사이클 + 동적 라우트(seed-only 금지):** *사용자가 만들 수 있는 엔티티*(게시판·차량·회의실…)는 ‘생성→네비 즉시반영(`revalidatePath("/","layout")`)→*새 slug* 로 진입 200(동적 라우트)→하위 CRUD 가 자기 컨텍스트로’ 를 한 줄로 검사. 시드 읽기만 보면 *생성 흐름*이 통째로 빠진다(intra 2026-06-25 게시판 추가→사이드바 미반영·404·글 오복귀). 정본 [[crud-lifecycle-and-dynamic-routes]].
4. **`tc-audit.mjs` — TC 행동(‘사람이 봐라’를 자동화):** hover펼침·opacity흐림·입력검증·이동목적지·역할게이트·+N건 등 — *시안 소스(:hover/opacity/검증로직)에 박혀 자동 판정 가능*. 사람 잔여는 외부 메일클라 렌더·실기기 터치뿐. *시간 의존 케이스는 동적 탐색/생성*.
5. **`toast-fidelity.mjs`·`text-fidelity.mjs` — 정적 텍스트 카탈로그(시안 소스 ↔ impl 소스 문자열, 정적·브라우저 불필요):** 토스트·placeholder·confirm/empty/error **헤딩** 처럼 *핸들러·속성·닫힌 모달*에 사는 텍스트는 ①의 렌더-DOM diff·③의 "뜨는가"를 다 빠져나간다([[fidelity-gaps-hide-in-non-default-states]]). 시안에서 문구를 뽑아 impl 문자열 리터럴과 전수 대조. **두 규칙(실증):** ⓐ impl 추출은 *단일행* 문자열만(`[^"\n]`) — 개행 포함 정규식은 JSX 를 통째 삼켜 거짓갭 양산. ⓑ 변수/맵 공급 값(`placeholder={MAP[k]}`)을 놓치니 *일반 단일행 리터럴*도 보조 haystack 으로. **승인 divergence 필터**(impl 이 시안 오타를 의도적 교정 등)는 사유와 함께. ★이 축이 *문구만이 아니라 구조·안전 갭*도 잡았다(intra: 게시판만 삭제 확인모달이 없던 것 = 다이얼로그 헤딩 대조로 발견 → `BoardDeleteButton` 보강).
6. **`vrt.mjs` — 시각회귀(동작-후 픽셀 모양):** 소스 diff·존재검사가 못 보는 *모양*(모달·토스트 렌더)을 베이스라인 픽셀 diff 로. **함정 4개(전부 실증):** ⓐ **풀페이지 캡처** — element-clip(`locator.screenshot`)은 배경 비침 artifact. ⓑ **환경 간 폰트 AA** — 풀페이지 텍스트는 머신/세션 간 폰트 힌팅으로 diff → pixelmatch `threshold:0.2` + 실패기준을 *백분율*(>0.5%)로(픽셀수 고정 금지). ⓒ **동적값 마스킹** — 이름·시각은 Playwright 내장 `mask`(정적 문구 토스트는 불필요). ⓓ **베이스라인 눈검토 필수** — 전환 중 반투명·clip 비침을 정답 삼으면 VRT 무의미(2번 걸러냄). 베이스라인은 *환경별*(CI 는 고정 Docker 렌더 필요).
- **`inspect.mjs` (+ `npm run inspect`):** 위 6종을 *정해진 순서로 한 번에*(싼 정적 ①②⑤ → 동적 ③④⑥) + 앞뒤 `db:reset` bookend + 통과/확인필요 요약. exit code 로 신호.
- **CI 필수 게이트(정적 축만):** ⑤(+`--ci` 로 미승인 갭=exit 1)를 머지 전 required check 로 — 순수 node(의존성·브라우저·DB 불필요)라 CI 에서 싸게 돈다. ★시안 소스가 `.gitignore`(비공개)면 추출 문구를 **커밋된 스냅샷**(`scripts/.fidelity/*.json`, 로컬 `--snapshot` 갱신)에 박고 시안 없으면 폴백 → 시안 없이도 게이트. 동적 ③④⑥은 무거워 로컬/pre-push.

## 두 가지 최적화(매번 같은 삽질 제거)
- **노이즈 자동 필터:** 반복 노이즈(성공상태 의존·샘플데이터·모달뒤 배경chrome·의도적 차이·데이터의존[③④가 setup로 커버])를 `isNoise()` 로 걸러 ①이 *진짜 갭만* 띄움(억제 건수 투명 표기). ★과억제 주의 — 보수적으로.
- **검증 속도 규율:** `tsc` → 영향 테스트만 → 직접 프로브 → **전체 스위트는 마지막 1회.** 같은 변경 재확인 반복 금지(서버 과부하→무관 테스트 timeout→오진. [[fast-feedback-not-timeouts]]).

## 부트스트랩 순서 (새 프로젝트)
1. 시안 시스템 먼저 스캔(공유 토큰·디자인시스템 정의 화면) → 화면↔라우트 매핑표.
2. ①② 부터(정적·읽기 — 싸다) → 화면 1번부터 돌림. ③④ 는 동작 생기면 추가.
3. **새로 만난 실패모드는 즉시 해당 스크립트 케이스 표에 추가**(prose 말고 코드) — harness 복리.
4. 통과 = "묶음 소진" 이지 "깨끗 증명" 아님([[verification-is-layered-zero-isnt-clean]]) — 보고는 "N종 소진, 안 돌린 건 여기".

## 한계 (정직히)
- 대상 repo 의 감사 *스크립트*는 그 DOM·라우트·시안에 묶여 *그대로 안 옮겨간다* — 이 레시피·intra 골격을 적응시켜 **다시 만들어야** 한다(빠르게).
- **정적 텍스트 카탈로그(⑤)의 경계:** 문자열 *리터럴*은 잡지만 **JSX 보간 본문**(`<p>{name} 차량과…</p>`)은 못 잡는다 — 그건 *닫힌 모달·빈상태를 실제로 렌더해* 대조하는 렌더-상태-매트릭스(①의 비기본상태 확장, 더 무거움)의 영역. ⑤로 "0" 이라고 본문 충실까지 증명된 건 아니다.
- **환경 의존성:** ⑥ VRT 베이스라인과 ③④⑥ 의 결과는 *dev 환경 상태에 민감*. 광범위/이미지계열 timeout 은 코드 회귀 전에 **장기가동 dev degraded**(예: sharp `decode-fail` — 네이티브 모듈 노화)부터 의심, *재시작이 근본*([[fast-feedback-not-timeouts]]). 별도 프로세스의 같은 라이브러리가 멀쩡하면 = 런타임 노화 확정.
- "안다 ≠ 실수 안 함." 진짜 방지책은 *일찍 만들어 `npm run inspect` 를 매 변경마다 도는 것*. 문서는 거들 뿐.

# 패턴 — 무료·빠름·비공개 트릴레마 — LLM 제품 의사결정틀

> 승격: 2026-06-18 (`/retro` 아카이브 채굴). 근거: `archive/llm-wiki/knowledge.md`("★지배 제약 — 무료·빠름·비공개 트릴레마")·`archive/llm-wiki/ideas.md`. ⚠️ company-internal 일반화.

## 결정 (fork) — 무슨 갈림길인가

사내/온프레미스 LLM 제품을 시작할 때 **비용·프라이버시·하드웨어 세 제약 중 어느 둘을 잡고 하나를 양보할지** 결정해야 한다.

- **무료 + 비공개(로컬)** → 빠름·품질 양보. GPU 없는 CPU-only 환경에서 더 심각.
- **무료 + 빠름(외부 무료 API)** → 프라이버시 양보. 사내 데이터 외부 전송·학습 위험.
- **빠름 + 비공개(유료 API·온프레 GPU)** → 돈 양보. 종량 과금 또는 하드웨어 투자.

"GPU 없음 + 추가비용 0 + 다수 동시사용 + 온프레미스" 네 가지를 동시에 만족하는 경로는 없다. 하나는 반드시 좁혀야 한다.

## 계기·증거 — 어느 프로젝트에서 무엇이 실패·통했나

llm-wiki 개발 과정에서 "GPU 없음 + 추가결제 0 + N명 동시사용 + 온프레미스" 를 동시에 성립시키려다 막혔다. CPU-only 소수 파일럿으로 범위를 좁혀 저동시성을 감내하는 방식으로 출발했고, 이후 설계에서는 세 꼭짓점 중 무엇을 양보하는지를 먼저 명시하는 것이 재설계 비용을 줄인다는 교훈이 남았다.

## 선택지와 트레이드오프

| 선택 | 얻는 것 | 잃는 것 |
|---|---|---|
| 로컬 모델 (무료 + 비공개) | 비용 $0, 데이터 외부 전송 없음 | 속도 느림, 품질↓ (GPU 없으면 심함), 동시성 제한 |
| 외부 무료 API (무료 + 빠름) | 비용 $0, 응답 빠름, 높은 동시성 | 사내 데이터 외부 전송·학습 위험, 프라이버시 통제 불가 |
| 유료 API / 온프레 GPU (빠름 + 비공개) | 응답 빠름, 품질 유지, 데이터 통제 | 종량 과금 또는 GPU 하드웨어 투자 |

**법적 경계(어느 선택에나 공통)**: 개인 구독 OAuth를 앱/SDK 백엔드로 자동 사용하거나 팀 요청을 프록시하는 구조는 약관 위반·밴 위험이다. 운영자 본인이 CLI로 직접 사용하는 경로만 추가비용 없이 합법적으로 동작한다($0).

## 언제 이대로 · 언제 다르게

**이대로(3제약 프레임 적용)**
- 사내/온프레미스 환경에서 LLM 기반 제품 아이디어가 나올 때.
- "무료로 할 수 있지 않을까?" + "데이터를 밖에 보내면 안 돼" + "GPU는 없어"가 동시에 등장할 때.
- 공급자 선택 또는 배포 방식을 결정하기 전에.

**다르게 볼 때**
- 비공개 요건이 없는 실험·비민감 데이터라면 외부 무료 API를 단순 선택해도 된다(트릴레마 경계 밖).
- 예산이 이미 확보된 경우라면 트릴레마 자체가 제약이 아니다 — 바로 유료/GPU 경로로 진입.
- 단일 사용자 CLI 자동화라면 개인 구독 CLI 직접 호출($0)이 유효한 네 번째 경로다(다수 동시사용 조건 해소).

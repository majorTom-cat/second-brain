# 패턴 — 무료·빠름·비공개 트릴레마 — LLM 제품 의사결정틀

> 승격: 2026-06-18 (`/retro` 아카이브 채굴). 근거: `archive/llm-wiki/knowledge.md`("★지배 제약 — 무료·빠름·비공개 트릴레마")·`archive/llm-wiki/ideas.md`. ⚠️ company-internal 일반화.

## 문제
사내/온프레미스 LLM 제품의 공급자·배포 선택이 막연하게 시작된다.
비용·프라이버시·하드웨어 3제약이 동시에 걸리는데, 그걸 늦게 발견하면
개발이 어느 정도 진행된 뒤에야 재설계 비용이 발생한다.

## 패턴
**3제약으로 강제로 좁힌다.**

- ① **비용**: 구독 ≠ API. 종량 API는 대량 인제스트·반복 질의에 폭증한다.
- ② **프라이버시**: 사내 데이터를 외부 서버에 전송하거나 모델 학습에 쓰이면 안 되는 경우를 먼저 확인한다.
- ③ **하드웨어**: GPU 유무. CPU-only 환경에서 로컬 모델은 느리고 품질이 제한된다.

**무료·빠름(품질)·비공개 — 셋 중 둘만 동시에 성립한다.**
"GPU 없음 + 추가비용 0 + 다수 동시사용 + 온프레미스" 가 동시에 성립하면 하나는 반드시 양보해야 한다.
예: CPU-only 소수 파일럿으로 시작해 저동시성을 감내하는 식으로 범위를 좁힌다.

**법적 경계**: 개인 구독 OAuth를 앱/SDK 백엔드로 자동 사용하거나
팀 요청을 프록시하는 구조는 약관 위반·밴 리스크다.
운영자 본인이 CLI로 직접 사용하는 경로만 추가비용 없이 합법적으로 동작한다($0).

## 신호 (이 패턴을 써야 할 때)
- 사내/온프레미스 환경에서 LLM 기반 제품 아이디어가 나올 때.
- "무료로 할 수 있지 않을까?" + "데이터를 밖에 보내면 안 돼" + "GPU는 없어" 가 동시에 등장할 때.
- 공급자 선택 또는 배포 방식 결정 전.

# 패턴 — 단일 권한 계산처 (권한 로직을 한 곳에서만)

> 승격: 2026-06-18 (`/retro` 아카이브 채굴). 근거: `archive/llm-wiki/knowledge.md`("ACL 4 강제지점·단일 계산처"). ⚠️ company-internal 일반화.

## 문제
권한 체크가 여러 계층(라우터·서비스·UI·API)에 흩어지면 한 곳을 빠뜨려 누수가 생긴다.
새 기능을 추가할 때마다 권한을 "또" 직접 짜야 하고, 구현마다 미묘하게 달라 불일치가 쌓인다.
역할 모델이 바뀌면 수정해야 할 지점을 전부 찾기가 어렵다.

## 패턴
- **단일 계산처 함수** 하나(`canAct(subject, action, resource)` 형태)가 모든 권한 판정을 담당.
- 모든 **강제지점**(질의 입력·페이지 로드·인제스트·파일링 등)이 그 함수를 호출 — 직접 판정하지 않음.
  예: `canManageScope` 함수를 4개 강제지점이 공용으로 호출.
- 계산처가 archived·비활성·역할 없음 등을 이미 `false` 로 막으면, 새 기능(복원 버튼·AI 호출 등)이
  **자동으로** 권한 일관성을 가짐 — 따로 막는 코드를 추가하지 않아도 됨.
- UI 버튼 노출도 동일 계산처 결과를 그대로 읽어 **자동으로 숨김/노출** 결정.

## 신호 (이 패턴을 써야 할 때)
scope·visibility·역할(role)이 있는 멀티테넌트·ACL 앱이라면 항상 적용.
권한 판정 로직이 2곳 이상 보이면 즉시 → 한 곳으로 모아라.

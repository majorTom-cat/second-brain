# 패턴 — LLM 공급자 추상화 + tier 폴백 + 비용안전 다층게이트 (R4b 토대)

## 결정 (fork) — 무슨 갈림길인가

LLM 공급자 통합 설계에서 두 개의 독립된 갈림길이 있다.

**Fork A — 공급자 구조**: 단일 공급자 고정 vs 추상화 + 폴백 라우팅
- **단일 고정**: 구현 단순, 한 공급자에 묶임, 장애·한도 초과 시 대안 없음.
- **추상화 + 폴백**: 코드 무수정 전환·복원력 확보, but 복잡도 상승.

**Fork B — 비용 구성**: 무료 only vs 무료+유료 혼합 vs 구독 CLI($0)
- **무료 only**: 과금 사고 없음, 품질·동시성 상한 있음.
- **무료+유료 혼합**: 품질 선택지 확보, but 폴백 경로에서 실수 과금 위험.
- **구독 CLI($0)**: 운영자 본인 CLI 직접 사용만 합법(프록시·자동화 확장 시 약관 위반).

## 계기·증거 — 어느 프로젝트에서 무엇이 실패·통했나

llm-wiki 개발 중 비용·프라이버시·품질에 따라 공급자를 전환해야 하는 요구가 생겼다. 무료↔유료 공급자를 섞어 구성했을 때 폴백 경로에서 의도치 않게 유료 공급자가 호출되어 실수 과금이 발생했다. 또한 약한 모델(백업 공급자)에 무거운 편집셋을 그대로 전달하면 조용히 품질이 떨어지거나 실패했다. 이 두 실패가 ④(과금 다층게이트)·②(tier별 프롬프트 재선택) 요건을 만들었다.

## 선택지와 트레이드오프

| 선택 | 얻는 것 | 잃는 것 |
|---|---|---|
| 단일 공급자 고정 | 구현 단순, 디버깅 쉬움 | 공급자 한도·장애 시 전체 중단, 전환 시 코드 수정 필요 |
| 추상화 + 폴백 라우팅 | 코드 무수정 공급자 전환, 장애 복원력, 역할별 최적 공급자 분리 | 추상화 레이어 복잡도↑, 폴백 체인 관리 필요 |
| 무료 only | 과금 리스크 없음 | 품질·동시성 상한 존재 |
| 무료+유료 혼합 | 작업별 품질 선택 가능 | 폴백 경로 과금 사고 위험, 다층 안전게이트 없으면 실수 과금 |
| 구독 CLI $0 | 추가비용 없이 고품질 | 운영자 본인 직접 실행만 합법, 앱 백엔드 자동화·프록시 확장 불가 |

**추상화 선택 시 갖춰야 할 것 (선택 체크리스트)**:

① **공급자 추상화**: 단일 인터페이스(`callStructured` 형태)로 여러 공급자를 구조화 JSON 출력으로 통일. `.env`의 역할별 변수(`INGEST_PROVIDER`/`QUERY_PROVIDER` 등)만 바꿔 코드 무수정 전환. 인제스트와 질의는 최적 공급자가 다를 수 있으므로 전역 단일 변수보다 역할별 분리 우선.

② **자동 폴백 + tier별 프롬프트 재선택**: 1순위 공급자 한도(429)·오류 시 백업으로 재시도. 백업이 약한 모델이면 무거운 편집셋을 주지 않는다 — 서빙 모델 tier에 맞는 프롬프트를 재선택.

③ **컨텍스트 예산 관리**: 모델별 무료 TPM 한도에 맞춰 입력 페이지 수를 줄인다. 413(초과) → 같은 모델 축소-재시도. 엉뚱한 무료 공급자로 캐스케이드하지 않는다.

④ **★유료 비용안전 다층게이트**: 폴백을 유료 공급자 안에 가두고 무료로 캐스케이드 금지. UI에 '유료' 뱃지 + 확인 팝업. 기본은 무료 유지. 관리자 일일 토큰 상한 설정. "키를 넣으면 자동 활성" 구조는 경고 없이 실수 과금 위험 — 명시적 opt-in 필수.

⑤ **BYOK 키 저장**: API 키는 `.env`가 아니라 DB AES-256-GCM으로 암호화 보관(마스터키는 env 전용 — DB 유출 시에도 복호화 불가). 429 시 다음 키로 자동 회전. env 폴백 무회귀(점진 도입 가능). 화면·로그·에러 메시지에 키 값 미노출.

⑥ **⚠️런타임 CPU 함정**: 일부 구독 CLI는 배포 노드의 CPU 명령어셋에서 막힐 수 있다. 예: 특정 Bun 컴파일 CLI는 AVX 필수 → 구형 노드에서 `SIGILL` 크래시. Rust 컴파일 CLI는 이 문제 없음. **배포 전 `lscpu` / AVX 확인을 체크리스트로** 남긴다.

## 언제 이대로 · 언제 다르게

**이대로 (추상화 + 다층게이트 적용)**
- 비용·프라이버시 라우팅이 동시에 필요한 다공급자 통합.
- "공급자가 바뀌어도 코드를 건드리기 싫다" 또는 "과금이 모르게 나가면 안 된다"가 요건으로 명시된 때.
- second-brain R4b 라우팅 엔진 스펙 작성 전.

**다르게 볼 때**
- 단일 공급자로 충분한 소규모 프로젝트라면 추상화는 과투자다 — 단순 직접 호출로 시작하고, 전환 시점에 리팩터링.
- 유료 공급자를 전혀 쓰지 않는다면 ④(과금게이트) 체크리스트는 생략 가능.
- 배포 노드가 최신 CPU 확정이라면 ⑥(AVX 체크)는 생략 가능 (단, 체크리스트에서 제거가 아니라 "확인 완료"로 표기).

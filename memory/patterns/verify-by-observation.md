# 패턴 — 관찰로 검증: `done` 은 green 신호가 아니라 *직접 본 동작*

> 승격: 2026-06-20 (실 incident — 다른 세션이 시안 받아 "개발+테스트 done" 보고했으나 화면이 시안과 다르고 버튼 링크가 죽어 있었음).
> 근거(2+ 프로젝트 반복): `lessons/todo-toy.md`(테스트 green인데 진입점이 listen 안 함), `lessons/intra.md`("에이전트 보고를 믿지 말 것"·"거짓안심"·`npm test` 글로브로만 0개 실행), `lessons/rail.md` 7회차(이 incident). 사용자 정정으로 캡처.

## 결정 (fork) — 무슨 갈림길인가

"이 REQ는 끝났다(`done`)" 를 **무엇으로 판정하나**:

**① green 신호로 판정** — 테스트가 통과(`npm test` ok)하면 done 보고
vs **② 관찰된 동작으로 판정** (이 패턴) — 사용자가 보게 될 형태로 **실제 띄워서 동작을 직접 보고** done 판정. green 은 *입력 중 하나*일 뿐 *증거*가 아니다.

## 계기·증거 — 어느 프로젝트에서 무엇이 실패했나

- **이 incident (시안 개발)** — 한 세션이 디자인 시안을 받아 "개발+테스트 끝, 완료" 보고. 실제 화면은 **버튼·링크가 죽어 있고 시안과 다르게 뭉뚱그려** 구현됨. 단위 테스트는 green — 테스트가 *로직*만 보고 *시각 일치·링크 배선*은 안 보기 때문. green 하나를 done 의 대리(proxy)로 써서 **거짓완료**가 게이트에 올라옴.
- **todo-toy** — 단위/통합 테스트 전부 green인데 `node index.js` 가 listen 을 안 함(Windows ESM main-guard). 테스트는 함수를 직접 호출하므로 *기동 경로* 결함을 못 봄. → `/develop` **진입점 기동 smoke** 가 이걸 잡게 됨.
- **intra** — sonnet 위임 에이전트 자가보고는 "정상"이었으나 경계 테스트로 권한 불변식 누수·일관성 갭 발견("에이전트 보고를 믿지 말 것"). `npm test` 가 폴더인자로 **0개 실행**되는데 "tests pass"로 착각. 다형참조 FK 누락을 한 케이스만 테스트해 "DB가 막는다" **거짓안심**.

공통 원인: **약한 단일 신호(green/자가보고)를 관찰된 동작의 대리로 사용** → 신호가 안 보는 차원(시각·링크·기동·경계·전 케이스)에서 결함이 통과.

## 선택지와 트레이드오프

| | ① green 신호로 판정 | ② 관찰된 동작으로 판정 (이 패턴) |
|---|---|---|
| **속도** | 빠름(자동) | 느림(사람·기동 1패스) |
| **객관성** | 높음(재현 가능) | 사람 관찰 개입 |
| **놓치는 것** | 시각 일치·링크 배선·기동 경로·경계·전 케이스 | (관찰이 덮는 만큼 적음) |
| **거짓완료 위험** | 높음 — green = done 으로 오인 | 낮음 — 본 것만 done |

→ 둘은 배타가 아니다: **테스트는 회귀 방지로 유지**하되, `done` 판정의 *최종 근거*는 관찰. "테스트 green" 과 "관찰된 동작" 을 **분리해서 보고**한다.

## 언제 이대로 · 언제 다르게

- 이대로(② **관찰로 검증**) 할 신호:
  - **UI/화면 REQ** — 렌더 화면을 시안과 대조 + 모든 버튼·링크·폼 클릭스루(테스트가 구조적으로 시각·링크를 못 봄)
  - **기동 경로가 있는 서비스/CLI** — 실제 진입점 기동 후 health·기본 라우트(진입점 가드·바인드·시그널은 단위테스트 밖)
  - **위임(서브에이전트) 산출** — 자가보고 믿지 말고 경계로 직접 검증
  - **권한·불변식** — "허용되는 사람"뿐 아니라 "차단돼야 하는 사람"까지, 같은 불변식의 **모든 마스터** 케이스
- 다르게(① green 충분) 갈 신호:
  - **순수 로직·데이터·API REQ** 로 시각/인터랙션/기동 표면이 없고 acceptance 를 테스트가 전부 덮을 때 — 관찰 추가는 과투자
  - 단, 그 테스트가 **프로젝트 표준 명령(`npm test`)으로 실제 실행되는지** 한 번은 확인(intra: 글로브 안 맞아 0개 실행되면 green 이 거짓)

## ★ 공통 주의 (함정)

- **green 을 "증거"로 격상하지 말 것**: green 은 *그 테스트가 보는 차원*에서만 참. 안 보는 차원(시각·링크·기동·경계)은 여전히 미검증.
- **자가보고 = 미검증**: 사람이든 서브에이전트든 "정상입니다"는 관찰이 아니다 — 경계로 직접 친다.
- **"테스트 done" 과 "관찰 done" 을 같은 말로 보고하지 말 것**: 사용자는 done 을 *동작함*으로 읽는다.

# 패턴 — Design-ready 스킨: 구조 먼저, 비주얼은 토큰 1패스로 나중에

> 승격: 2026-06-18 (`/retro` 아카이브 채굴). 근거: `archive/agora/ideas.md`("Design-ready 스킨 흡수 키트"),
> `archive/agora/knowledge.md`(노하우 Design-ready). ⚠️ company-internal 일반화.

## 문제

디자이너의 최종 시안은 늦게 확정되지만 코드는 먼저 만들어야 한다.
비주얼을 기다리면 개발이 막히고, 임의 색·치수로 먼저 만들면 시안 도착 후 전 화면을 갈아엎는다.
기획↔디자인 분리·러프 반복 프로젝트에서 이 낭비가 반복된다.

## 패턴

### ① 디자인 토큰 단일 출처

- `globals.css :root` 에 모든 색·치수·간격 토큰 선언
- 컴포넌트는 `var(--token)` 만 참조 — 색·치수 하드코딩 0
- 러프 단계에서 임시값으로 채워도 구조는 완성: 시안 도착 시 `:root` 값만 교체

### ② 운영 데이터 색은 DB 마스터 필드로 분리

- 부서 색·자산 분류 색 등 운영 중 바뀌는 색상 → 디자인 토큰이 아니라 DB 레코드 필드
- 이유: 토큰은 브랜드 정체성(느리게 변함), 운영 색은 데이터(수시로 변함) — 섞으면 둘 다 관리 불가

### ③ `[data-theme="vN"]` 스킨 레이어로 안전하게 전환

```css
/* 러프 — 임시 토큰 */
:root { --color-primary: #888; --radius-card: 8px; }

/* 시안 도착 후 — 먼저 오버라이드로 비교 */
[data-theme="v2"] { --color-primary: #0050FF; --radius-card: 12px; }
```

- 새 디자인을 오버라이드로 먼저 입혀 기존 화면과 **나란히 비교** 후 `:root`로 승격
- 문제 발견 시 `data-theme` 속성만 제거하면 즉시 롤백

### ④ "디자인 이미지 → 토큰명" 빈 매핑시트를 docs에 미리 배치

```
docs/design-token-map.md
| 디자인 레이어명 | 토큰명 | 현재값(임시) | 확정값 |
|----------------|--------|-------------|--------|
| Primary/500    | --color-primary | #888 | (미정) |
```

- 시안 도착 즉시 디자이너·개발자가 함께 채움 → 토큰값 교체 1패스로 전 화면 일괄 스킨
- JSX/컴포넌트 코드는 거의 불변

## 신호 (이 패턴을 써야 할 때)

- 디자이너 시안이 개발보다 늦게 확정되는 프로젝트
- 러프부터 만들어 핸드백(HANDBACK) 루프가 예상될 때
- 브랜드 색·타이포·여백이 미확정인 채로 개발을 시작해야 할 때
- 기존 프로젝트에 전면 리디자인이 들어올 때 (→ [[ingest-convergence]] 그린필드 판단과 함께)

## 레일 적용 (빌드는 backlog)

- `/develop` 러프(`rough`) 단계: `REQ-SCR-NNN` 구현 시 컴포넌트에 토큰 골격만 깔고 임시값 사용
- `/develop` 풀(`full`) 단계 진입 조건에 "디자인 토큰 매핑시트 완성" 추가
- `spec-author` 스킬: 화면 REQ 작성 시 "토큰 출처 명시" 필드 포함 권고
- HANDBACK 게이트에서 이 패턴 체크리스트(토큰 단일 출처 · 운영색 DB 분리 · 매핑시트 존재) 검증
